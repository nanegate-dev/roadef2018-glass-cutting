Cut every item of a glass order from Saint-Gobain's jumbo plates, taken in their given order, with guillotine cuts of at most four stages, no item on a defect, no cut through a defect, and every stack of items cut in its order; smaller is better on the glass lost: the plates used, less the residual right of the last plate's last vertical cut, less the items' area, in whole square millimetres.

What this is. The ROADEF/EURO 2018 challenge, set by Saint-Gobain Glass France: "Cutting Optimization Problem Description" (18/05/2018) and its official checker (main.cpp, version 23/05/2018), on the fifteen instances of dataset B. Where the subject and the checker differ, the checker's rule is the rule here (the README lists every difference): stripe and strip size bounds bind branches only, the residual is the last node of the last plate, and the objective is the checker's OF. Plates are 6000 x 3210 mm, each with its own map of small rectangular defects from the float line. An item may be turned 90 degrees. The subject writes the objective as H W m - H r_m - sum of w_i h_i, with m the plates used and r_m the residual's width.

The cutting tree, in the subject's words. A plate is cut by 1-cuts, vertical, into stripes side by side; a stripe by 2-cuts, horizontal, into strips; a strip by 3-cuts, vertical, into pieces; a piece by at most one 4-cut, horizontal, into two. Each cut runs from edge to edge of the piece it cuts. Every part that is not cut further is an item, a waste, or the residual: the part right of the last 1-cut of the last plate, which is not lost. The items are cut in the order of a depth-first walk of the tree, children left to right (1- and 3-cuts) or bottom to top (2- and 4-cuts).

Units. EVERY LENGTH IS WHOLE MILLIMETRES AND EVERY AREA WHOLE SQUARE MILLIMETRES, in the instance and in the answer. There is no division anywhere in the rules.

The instance. instance.plate_w, plate_h: the plate, 6000 and 3210 in dataset B. n_plates_max: the plates available, 100. min1cut, max1cut: the least and greatest width of a stripe, 100 and 3500. min2cut: the least height of a strip, 100. min_waste: the least width and height of a waste, 20. item_w, item_h: each item's width and height, item k at position k (WIDTH_ITEM and LENGTH_ITEM of the batch file; the checker reads LENGTH as height). stacks: each stack as the list of its items in the order they must be cut. defect_plate, defect_x, defect_y, defect_w, defect_h: every defect of every plate, defect d the rectangle from (defect_x, defect_y) to (defect_x + defect_w, defect_y + defect_h) on plate defect_plate. name, source, best_180s, best_3600s and best_known are labels no rule reads (the best results of the challenge's 180 s and 3600 s runs and the best published, mm^2).

The solution. The tree as lists of equal length N, one entry per node, in depth-first pre-order: solution.plate (the plate the node is on), cut (its level: 0 for a plate, 1 to 4 for the cut that made it), type (an item's number 0 to n - 1, -1 a waste, -2 a branch, that is a node cut further, -3 the residual), x, y (its lower-left corner), w, h (its width and height), parent (its parent node, -1 for a plate) and end (one past the last node of its subtree). Then item_node, one entry per item: the node that cuts it; defect_leaf, one entry per defect of the instance: the waste leaf that contains it, or -1 on a plate not used; and three claims: n_plates, residual_w, geo_loss.

Why the certificate is enough. With parent and end every node checks locally that the list is the tree in pre-order: [i, end[i]) is i's subtree, its first child follows it, each next sibling starts where the previous sibling's subtree ends. The item order is then the order of the item nodes, so a stack's order is checked pair by pair on item_node. The children of every branch tile it exactly, so the leaves of a plate tile the plate; a defect inside one waste leaf is therefore inside no item and crossed by no cut, which is exactly the checker's test that every defect of a used plate lies wholly in one leaf and in no item.

Validity, as eleven conditions, checked in this order. Read every number of the solution as round(value): the value itself for a whole number, a refusal for anything that is not a number. n is the number of items; last is N - 1; m = plate[last] + 1, the plates used.
1. Shapes. solution.type has N >= 1 entries and plate, cut, x, y, w, h, parent and end have N; item_node has n entries and defect_leaf one per defect of the instance; every entry of the eleven lists and the three claims is whole (modulo 1 is 0).
2. The tree. For every node i: if cut[i] = 0, i is a plate: parent[i] = -1; plate[i] = 0 when i = 0 and plate[i - 1] + 1 otherwise; plate[i] < n_plates_max; i < end[i] <= N; and end[i] = N or cut[end[i]] = 0. Otherwise, with p = parent[i]: 0 <= p < i, plate[i] = plate[p], cut[i] = cut[p] + 1, i < end[i] <= end[p], and end[i] = end[p] or (end[i] < N and parent[end[i]] = p). And if type[i] = -2: end[i] >= i + 2, i + 1 < N and parent[i + 1] = i; otherwise end[i] = i + 1. So plates are used in order 0, 1, 2, ..., and a branch has at least one child.
3. Types and levels. Every type is -3, -2, -1 or 0 to n - 1; every cut is 0 to 4; a node with cut 0 has type -2; a node with type -2 has cut at most 3 (there is no fifth stage); a node with type -3 has cut 1 and is the last node.
4. Tiling. A node with cut 0 is the whole plate: x = 0, y = 0, w = plate_w, h = plate_h. For every other node i with p = parent[i], when 0 <= p < i < end[i] <= N and end[p] <= N (otherwise condition 2 refuses it): if cut[i] is odd (a 1-cut or a 3-cut, left to right), y[i] = y[p] and h[i] = h[p]; if i = p + 1 then x[i] = x[p]; if end[i] < end[p] then x[end[i]] = x[i] + w[i]; otherwise x[i] + w[i] = x[p] + w[p]. If cut[i] is even (a 2-cut or a 4-cut, bottom to top), the same with x and y exchanged and w and h exchanged.
5. At most one 4-cut in a piece. A node i with cut 4 that is not its parent's first child (i is not parent[i] + 1, with 0 <= parent[i] < i) is its last: end[i] = end[parent[i]]. So a node with cut 3 has at most two children.
6. Sizes. A node with type -2 and cut 1 has min1cut <= w <= max1cut; one with type -2 and cut 2 has h >= min2cut; a node with type -1 has w >= min_waste and h >= min_waste; one with type -3 has w >= min_waste.
7. Identity. A node with type k, an item, is item_w[k] wide and item_h[k] high, or item_h[k] wide and item_w[k] high.
8. Production. For every item k: 0 <= item_node[k] < N and type[item_node[k]] = k; and exactly n nodes have a type of 0 or more.
9. Sequence. For every stack, and every two items a, b next to each other in it, a first: item_node[a] < item_node[b].
10. Defects. For every defect d: defect_leaf[d] is -1, or it is a node L with 0 <= L < N, plate[L] = defect_plate[d], type[L] = -1 or -3, x[L] <= defect_x[d], defect_x[d] + defect_w[d] <= x[L] + w[L], y[L] <= defect_y[d] and defect_y[d] + defect_h[d] <= y[L] + h[L]; and defect_leaf[d] is not -1 when defect_plate[d] < m.
11. The claims. n_plates = m; residual_w = w[last] when cut[last] = 1 and type[last] is -1 or -3, and 0 otherwise (a waste left by the last 1-cut of the last plate is the residual, as the checker counts it); geo_loss = n_plates x plate_w x plate_h - plate_h x residual_w - the sum over the items of item_w x item_h.
Conditions 2 to 5 are the guillotine tree; 6 to 10 read only what 2 to 5 proved; 11 is what the objective reads.

Objective, MINIMISED: geo_loss, which condition 11 proves is the plates used, less the residual, less the items' area: the checker's OF, in mm^2.

What a solution may choose is the tree: how each plate is cut, which item goes where and turned or not, and so how many plates are used. It may not change the plates, their order, their defects, the items, the stacks or the cut rules; a claim or a pointer that does not recompute is refused whatever the tree says.
